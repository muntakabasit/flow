## How future DAWT Design contributions reach Flow

**Default written destination:** add a versioned, public-safe Markdown contribution under `docs/design/dawt-design/` in this repository; update this register; reference the new document from the existing [Flow owner issue #1](https://github.com/muntakabasit/flow/issues/1) when a receiving decision or cross-worker handoff is requested.

Every contribution should identify:

1. **Human intention and original source** with a verifiable link or safe private reference.
2. **Owner and authority:** what is adopted, held, untested, hypothetical or not permitted.
3. **Design judgement:** what mechanism improves a real task, with reasons and an alternative where relevant.
4. **Human-evidence gate:** what actual on-device or practical evidence is missing.
5. **Explicit return:** what the Flow owner/Claude should read, inspect, accept, revise or reject.
6. **Exact STOP:** no new build, source access or consequential action without the proper owner and governance admission.

**If the source is private, protected or published only to a specific private artifact:** publish a **sanitised assessment and provenance-only pointer**, not raw messages, excerpts, tokens, credentials, exact private artifact addresses or personal records. Keep the full copy in its authorised local project. General permission to archive design work is **not permission to publish someone's underlying source material.**

**Verification rule:** GitHub file existence ≠ owner acceptance; an Issue comment ≠ a live Claude session read; a rendered screenshot or passing script ≠ successful human encounter.
